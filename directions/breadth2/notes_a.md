# Notes A: two directions

Dates: today is 2026-11-13. Quotes were obtained through WebFetch (a small model that sometimes refused long quotes); where it only gave paraphrase I say so. Items marked "unverified" came from search snippets only.

## Direction 1. Mixed-version / rolling-upgrade compatibility

### Real failures
1. TiKV (Rust), rollback panic, 2021. https://github.com/tikv/tikv/issues/11226 (opened Nov 3, 2021).
   Quote: "failed to load_latest_options \"Invalid argument: Unable to parse the specified CF option disable_write_stall\"". Cause per issue: tikv/rocksdb#252 added a CF option, and "lower versions that are unaware of this item can't parse options file." Workaround: "First rollback to version v5.0.4 or v5.1.2, then rollback to the desired version." Context: the fix was making old versions tolerate unknown items, so safe rollback depends on a chain of intermediate versions. FACT (source above).
2. TiKV (Rust), new version cannot read old files, 2021. https://github.com/tikv/tikv/issues/10774 (Aug 18, 2021). Quote: "TiKV with Titan enabled upgrade from 3.x versions to >=4.0 versions." Cause: format change tikv/titan#109 "didn't handle older files"; reads raised false-positive errors. It appeared only after a second upgrade (to 5.1.1), not after 3.x->4.0.9. FACT; the quoted wording is partly paraphrase by the fetch tool.
3. TiDB (Go), mixed 8.5.8/8.5.9, 2026. https://github.com/pingcap/tidb/issues/72744 (Nov 5, 2026). Quote: "reads the base table and DATE_ADD control successfully, but reading the ADDDATE view fails." Error: `ERROR 1105 (HY000) ... near "QUARTER) AS ..."`; "the parse error points into the stored definition." Closed not planned: "v8.5.8 does not support this ADDDATE syntax, so this is not a regression". Insight (INFERENCE): a new node persisted a definition (SQL text) that an old node's parser rejects; nobody's spec says the old version must read what the new version writes.
4. ScyllaDB (C++), mixed cluster returns wrong data, 2025. https://github.com/scylladb/scylladb/issues/24172 (May 15, 2025). Quote: "In mixed cluster query could return wrong data." Assertion: "Lists differ: [[None], [0]] != [[None], [0], [2]]". Closed as duplicate of #23313 ("tablets: fix missing data after tablet merge"). Note: the root cause is a tablet-merge bug, not clearly a format bug; weak example.
5. tellus (Rust actor framework), 2026. https://github.com/tellus-rs/tellus/issues/261 (Nov 6, 2026). Quotes: "postcard writes a struct's fields in declaration order, with no names and no field numbers." and "The swapped fields are the case the docs warn about: postcard delivers them silently wrong." Merged fix adds versioned schemas and version info in the handshake. FACT. Small project, but it is the cleanest Rust serde statement of the problem: positional serde formats (postcard, bincode) silently mis-decode.
6. rift-cluster (Rust), 2026. https://github.com/achird-labs/rift-cluster/issues/710 (Oct 18, 2026). Quote: "A **decode widening** (a field that accepts a wider type) still makes old binaries unable to read what new ones commit." and "The rule to cite is 'no config writes until every node is upgraded'." Small project. FACT.
7. vtop-engine (Rust, Raft metadata tier), 2026. https://github.com/allamiro/vtop-engine/issues/554 (Oct 14, 2026). Quotes: "The metadata Raft tier has no mixed-version story, but the Helm chart rolls it with `RollingUpdate`." and "an upgraded voter wins leadership and proposes a command the old voters cannot decode, so they cannot append". The author states the scenario was inferred, not reproduced. Fix merged: a feature level gates new command kinds. Small project; the Raft-log plus rolling-update shape is the interesting part.
8. Industry-scale evidence: the SOSP'21 study (below) reports 120 upgrade failures; UpFuzz (NSDI'26) abstract: "Data format incompatibility is a significant cause of cloud incidents during distributed system upgrades". I did not find a fresh named big-vendor postmortem for 2025-26 (search came back empty). Gap in my evidence.

All the Rust hits are small or old (TiKV). Claim: "widely used Rust distributed system with a recent upgrade outage" is not shown by what I found. TiKV, 2021, is the best.

### Property to verify (OPINION: my formulation)
Mixed-version safety of a protocol P with versions V1..Vn: for every reachable state of the system where each node runs any version in a set S allowed by the rollout policy (including rollback), (a) every message or persisted record written by version i is either decoded by version j with the same abstract meaning or rejected by an explicit, total "unknown/newer" path that leaves protocol invariants (e.g. Raft log matching, linearizability) intact; (b) the protocol's safety invariant holds in the product of the versions' transition relations. Sub-property for the codec layer: for each type T and version pair (i,j) in the rollout policy, decode_j(encode_i(x)) = project(x) or Err(Unknown), never a different valid value (rules out postcard field-swap).

### Closest prior work
- Zhang, Yang, Jin, Sethi, Rodrigues, Lu, Yuan, "Understanding and Detecting Software Upgrade Failures in Distributed Systems", SOSP 2021. https://yonglezh-purdue.github.io/files/sosp21-upgrade.pdf . Empirical study of 120 failures; DUPTester (testing) and DUPChecker (static data-syntax check, 878 potential incompatibilities in 7 systems). Open: testing/static only, no proof; no protocol-level semantic check. Collected.
- Han, Sruthi P C, Wang, Song, Papan, Fonseca, Zhang, "UpFuzz: Detecting Data Format Incompatibility Bugs during Distributed Storage System Upgrade", NSDI 2026. https://www.usenix.org/system/files/nsdi26-han.pdf . 15 new bugs in Cassandra, HBase, HDFS (6 crash the cluster, 4 lose or corrupt data). Open: fuzzing, JVM systems, storage formats; no Rust; no guarantee. Collected.
- Chait-Roth, Namjoshi, Wies, "Consistent Updates for Scalable Microservices", arXiv 2508.04829 (2025). https://arxiv.org/abs/2508.04829 . Abstract: "the first algorithms that guarantee consistency for mixed-mode updates", relying on semantic properties such as commutativity; proves semantically oblivious methods must allow inconsistencies. Open (INFERENCE): models stateless workers over a shared store, not replicated protocols with their own wire format (Raft peers), and not implementation code. Collected.
- Schultz, Dardik, Tripakis, "Formal Verification of a Distributed Dynamic Reconfiguration Protocol", CPP 2022. https://arxiv.org/abs/2109.11987 . Proves reconfiguration (membership) safety in TLA+; not software-version change. Already in the collection.

### Tractability
- FACT: no machine-checked rolling-upgrade proof found in my searches (search was shallow; absence is not proof).
- OPINION: tractable in two layers. (i) Codec layer: a Rust tool (serde-derive analysis or a Verus/Kani check) that proves the decode/encode cross-version property above for a pair of type definitions, flagging positional formats; moderate, but risks being "a lint". (ii) Protocol layer: model version as part of node state in TLA+/Ivy, prove Raft or a store's invariants when nodes disagree on command set (feature-level gating, as in the vtop fix, is the thing to prove); PhD-scale if the target is a real system (TiKV/raft-rs) and conformance to code is established. Main risk: reviewers see it as engineering unless a general theorem (e.g. gating-sufficiency) comes out.
- OPINION: the human's "no hot-path" filter is met; this is control/storage format, not performance code.

I did not check each one for upgrade bugs; only TiKV is evidenced above.

## Direction 2. HTTP parsing differentials across proxy chains (Rust)

### Real failures
1. Pingora, CVE-2025-4366 (RUSTSEC-2025-0037, GHSA-93c7-7xqw-w357), cache-enabled request smuggling. https://blog.cloudflare.com/resolving-a-request-smuggling-vulnerability-in-pingora/ Reported Apr 11, 2025, public May 22, 2025, fixed in pingora 0.5.0. Quotes (via fetch tool): "when caching was enabled, this logic was skipped on cache hits." and "any unread request body left in the HTTP/1.1 connection could act as a vector for request smuggling." Context: normally Pingora consumes the body or refuses to reuse the connection; the cache-hit path skipped this. Fix commit fda3317 (per secondary summary) always drains the body. FACT. Note: this is a connection-state bug (body left on a reused connection), not a grammar bug.
2. Pingora, CVE-2026-2833 / RUSTSEC-2026-0033 / GHSA-xq2h-p299-vjwv, Mar 5, 2026. https://github.com/cloudflare/pingora/security/advisories/GHSA-xq2h-p299-vjwv . Quote: "Pingora versions prior to 0.8.0 would immediately forward bytes following a request with an Upgrade header to the backend ... without waiting for a 101 Switching Protocols response." and "This allows an attacker to smuggle requests to the backend and bypass proxy-level security controls." Rated Critical 9.3. Cloudflare CDN not affected. FACT.
3. Pingora, CVE-2026-2835 / RUSTSEC-2026-0034 / GHSA-hj7x-879w-vrp7, Mar 5, 2026. https://github.com/cloudflare/pingora/security/advisories/GHSA-hj7x-879w-vrp7 . Quote: "Pingora versions prior to 0.8.0 improperly allowed HTTP/1.0 request bodies to be close-delimited" and "incorrectly handled multiple Transfer-Encoding values." and "This allows an attacker to desync Pingora's request framing from backend servers and smuggle requests to the backend." Cloudflare's ingress "rejected ambiguous framing" so its CDN was not affected (fetch-tool wording). A third one, CVE-2026-2836 (cache poisoning, RUSTSEC-2026-0035), is from a search snippet only (unverified). Cloudflare write-up: https://blog.cloudflare.com/pingora-oss-smuggling-vulnerabilities/ (not fetched).
4. actix-http (Rust), RUSTSEC-2026-0446 / GHSA-2q7f-mf9f-5qhr, Nov 6, 2026. https://rustsec.org/advisories/RUSTSEC-2026-0446.html . Quote: "The HTTP/1 chunked decoder accepts a bare line feed after the final chunk as the start of a trailer instead of rejecting the malformed request." and "An attacker can use this difference in request parsing to bypass access controls enforced by a proxy or web application firewall." Fixed in 3.20.2. FACT.
5. hyper (Rust), 2021. https://github.com/advisories/GHSA-6hfq-h8hq-87mf (CVE-2021-21299, RUSTSEC-2021-0020): multiple Transfer-Encoding headers where hyper treated `Transfer-Encoding: chunked` + `Transfer-Encoding: cow` as chunked. Also RUSTSEC-2021-0079 (CVE-2021-32714, chunk-size integer overflow, "in rarer cases, a request smuggling attack") and RUSTSEC-2020-0008 (GET bodies). Wording from search summaries, not fetched verbatim (unverified). No hyper smuggling advisory found for 2022-2026: FACT about my search only.
6. Non-Rust but same class, from search snippets (unverified): Netty and Jetty chunk-extension quoted-string smuggling (GHSA-pwqr-wmgm-9rr8, GHSA-355h-qmc2-wpwf); http4s Ember CVE-2026-69204 (accepts both Content-Length and Transfer-Encoding).

Pattern (INFERENCE): the Rust bugs are of three kinds: (a) grammar leniency (TE list, bare LF, HTTP/1.0 close-delimit); (b) connection-state bugs (unread body on cache hit, bytes forwarded before 101); (c) integer parsing. Memory safety does not prevent any of them.

### Property to verify (OPINION: my formulation)
Let a proxy P be modelled as a transducer from a byte stream to (forwarded byte stream, decisions), and the backend B as a parser on a byte stream. Framing-agreement: for every input stream s accepted by P, parse_B(P(s)) yields the same sequence of message boundaries and the same (method, target, headers) as P's own parse of s, or P rejects. Equivalently, P's output is in a canonical sublanguage L on which every conformant RFC 9112 parser agrees (determinism of framing). Corollary: after any message, P's connection state is "at a message boundary" before reuse (rules out bug 1) and no bytes are relayed in a mode before the mode switch is confirmed (bug 2).

### Closest prior work
- Kallus, Anantharaman, Locasto, Smith, "The HTTP Garden: Discovering Parsing Vulnerabilities in HTTP/1.1 Implementations by Differential Fuzzing of Request Streams", arXiv 2405.17737 (2024). https://arxiv.org/abs/2405.17737 . 122 unique discrepancies, 68 patched; origin servers, transducers (proxies), echo servers. Open: finds bugs, proves nothing; Rust implementations are targets only as black boxes. Collected.
- Jabiyev, Sprecher, Onarlioglu, Kirda, "T-Reqs: HTTP Request Smuggling with Differential Fuzzing", CCS 2021. https://swsprec.com/papers/treqs.pdf . Grammar-based differential fuzzing of CDN/proxy pairs. Open: same. Collected (author list partly from memory; check against the PDF).
- Search found no machine-checked HTTP/1.1 framing proof (queries covered Coq, Verus, EverParse). One hit, "Access Control as Verified Parse Constraints", arXiv 2609.12488, uses EverParse for HTTP requests on seL4 but is about access control, not smuggling (from a search snippet; not fetched). Another hit, arXiv 2606.10649 "Layer Order Semantics for Automata-Based Cybersecurity", models smuggling as two-parser mismatch (snippet only). I did not download these two.
- Other verified-parser tools (OPINION: from my background knowledge, not checked now): EverParse (Microsoft Research), Vest (Verus-based). Needed for the "what exists" slot.

### Tractability
- FACT: the bug class is recurring in Rust, including Cloudflare's flagship proxy in 2025 and 2026.
- OPINION: the grammar half (framing agreement for HTTP/1.1 per RFC 9112) is well bounded and could be proved for a spec-level parser, then for an implementation extracted or checked in Verus/Creusot against it. This is a doable thesis chapter, but it is single-machine parsing and not distributed; it conflicts with the human's "distributed preferred" filter unless the contribution is the multi-hop part. The distributed part is the theorem about a chain P1..Pk of heterogeneous parsers: which canonicalization (reject-ambiguous) at the first hop makes the whole chain agree, regardless of the later parsers. That is novel as far as I found, but I did not do a deep literature search.
- Connection-state bugs (CVE-2025-4366, CVE-2026-2833) are protocol-state-machine bugs: tractable with typestate or a verified state machine in the proxy core; closer to ordinary software verification.
- Risk (OPINION): the prior is that the practical effect is limited, because most deployments reject ambiguous input at the edge (Cloudflare said its ingress did). Also no hot-path claim here: the parsing is hot-path code in Pingora; the human's filter requires real bugs, and we do have real bugs.
