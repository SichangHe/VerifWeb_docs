# Verus proof audit
(authored by agents unless marked 🧑)

The original smallbitvec pointer specification is unsound: it proves `assert(false)`. The corrected version rejects that counterexample. Other findings concern claims stronger than the checked specifications, not demonstrated contradictions.

## Findings

1. **Unsound pointer assumption.** The old declaration requires `p@.addr + i * size_of::<T>() <= usize::MAX + 1` and promises `r@.addr == p@.addr + i * size_of::<T>()`. Calling it with address 1 and offset `usize::MAX` for `u8` promises an address outside usize. The existing contradiction reruns with “verification results:: 97 verified, 0 errors”. This affects the old full/heap proofs and their negative-test copies. The corrected allocation-aware wrapper gives “96 verified, 0 errors”; invalid-offset and false-assertion probes fail. Exact contracts, files, and logs: [smallbitvec audit](SBV.md).

2. **Unverified parser and callback bodies.** The nth parser trusts `#[verifier::external_body]` with `ensures r <= 0` and body `{ unimplemented!() }`. Replacing it with constant zero verifies, including for inputs where zero is the wrong parsed value. Its `assert(false)` probe fails. The scheduler similarly trusts `fn run_job(id: u64) -> (out: Vec<Item>) { unimplemented!() }` with no postcondition; its false-assertion probe fails. These panicking stubs do not establish executable parser/callback correctness. See [CSS audit](CSS_MISC.md) and [scheduler audit](GC_ISO.md).

3. **Accepted contracts permit wrong functional behavior.** Checked mutations return zero for all negative decimal parses, erase visible x overflow, always select table rule 6, and round -1 app unit to -1 pixel instead of zero. The respective reports claim stronger behavior. Search and rectangle-intersection models also accept always-`None`, but their reports explicitly limit their claims to conditional bounds/containment. The proposed Blob fix proves saturating addition, yet a checked negative nested-slice example selects the wrong start. See [CSS/miscellaneous](CSS_MISC.md), [layout](LAYOUT.md), and [other proofs](OTHER.md).

4. **GC and isolation comments exceed theorems.** The ephemeron comment says “and conversely every marked node is reachable (no over-retention)”, but its contract only requires closure; a checked two-node example marks a node unreachable by strong edges. The resurrection formula proves failure of direct-root inference, not unconditional collection despite other roots. The external-pointer-table contract proves tag/payload membership, not the installation history claimed by a comment. See [GC/isolation audit](GC_ISO.md).

5. **One advertised passing file is rejected.** The fragment report says “Files (all verify”; `arc.rs` instead reports “error: loop must have a `decreases` clause”. Several layout claims also omit axis, saturation, count, or source-correspondence restrictions. Details and complete quotations: [layout audit](LAYOUT.md).

## Scope and interpretation

The inventory scans all Rust files under `out` for Verus syntax/imports and checks candidates for a `verus!` block. A secondary scan for `proof fn`, `spec fn`, verifier attributes, and builtins found no additional original proofs. Ordinary upstream Rust, Kani programs, copied verifier implementation files, and three connector files matching the word `verifier` are not Verus proofs. Explicit exclusions are in [inventory.json](inventory.json).

The original corpus contains **150 paths, 83 distinct contents**: 48 distinct inputs pass (87 paths), and 35 are rejected, including two before reporting counts. Byte-identical copies share one verification run; every path is listed below. All original contents were rerun in this audit with `tools/verus-x86-linux/verus FILE --crate-type=lib --multiple-errors 10`, version `0.2026.11.02.8bf68ee`, with a 180-second timeout per input; none timed out. [results.json](results.json) records exact commands, exit codes, counts, hashes, and paths; [logs](logs/) contains complete outputs. Fourteen audit probes are listed separately and are not original proof claims.

“Sound” means no unsound local trust, impossible overall precondition, or claim mismatch found within the stated model. It is not a proof of Verus/vstd, the solver, or correspondence to upstream execution. “Unsound” means a trusted contract admits contradiction. “Overstated” means the accompanying claim exceeds the theorem; a sound restricted contract may still receive this verdict. Rejected inputs have no accepted whole-file theorem, so they are marked **rejected**, rather than incorrectly called sound. A rejected file can still contain the same unsound assumption.

No globally impossible API precondition was found. Component reviews give concrete admissible cases and distinguish contradictory internal branches from vacuous APIs. This is source review plus selected checked witnesses, not an exhaustive machine-checked satisfiability proof of every helper. Standard Verus/vstd trust remains outside this audit. The per-file entries include custom trusted items and explicit target/layout declarations; no other local assumptions, admissions, external declarations, or user axioms were found.

To refresh all runs, execute `python out/cx_proofs/rerun.py --fresh`; without `--fresh`, the script verifies only new contents and preserves prior results. The scripts deduplicate by file bytes; all discovered proof files here are standalone inputs. Source proofs were not edited.
