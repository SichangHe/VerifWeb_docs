# Independent review of URL and sanitizer claims
(authored by agents unless marked 🧑)

Reviewed 2026-11-04. The concrete URL divergences, debug panic, Verus result, and sanitizer fixed-point failures reproduce. Correct the novelty claims, the WPT interpretation, and the claim that a scripting-disabled parser alone demonstrates XSS. No issue was filed and no maintainer was contacted.

## Most important corrections

1. **Wrong: N1 is apparently new.** rust-url already has [PR #1159, “Fix tab or newline after a drive letter”](https://github.com/servo/rust-url/pull/1159), opened 2026-10-19. Its description says: “Without `\r`, `X:..` is still pending and the segment remains correct. With `\r` it writes `X:` early so we end up with `file:///X:/..` hence the URL changes on re-parse.” Its regression tests include `("file:X:\rfoo", "file:///X:foo")`. This is the reported mechanism and input family, not merely a nearby issue. Saved response and patch: [pr1159.json](pr1159.json), [pr1159-files.jsonl](pr1159-files.jsonl).

2. **Wrong: D6 is apparently unreported.** [rust-url #1123](https://github.com/servo/rust-url/issues/1123) explicitly says: “`a:  ?` is already supposed to result in `a: %20?` (though currently doesn't...).” Its title concerns `set_path`, but its body reports the parser behavior too. WPT also already tests it. Saved source: [issue1123.json](issue1123.json).

3. **Overstated: “real XSS” and “live `onerror`” from DOMParser/mail clients.** The custom allowlist preserves an event-handler payload, and scripting-disabled reparsing creates an `img` with `onerror`. That is confirmed. Execution in a browser/application was not tested. [MDN, DOMParser.parseFromString](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString) says: “events are not fired, and event handlers aren't called to run inline scripts.” It separately says: “event handlers and scripts in its DOM will be able to run if they are inserted into the visible DOM.” State the required activation/insertion step and call the present result a potential XSS path. Mail-client execution is unverified. Saved page: [domparser.html](domparser.html).

4. **Wrong: 69 parser/href failures excluding blob origins.** Re-running the supplied harness produces 69 total failures, comprising 50 href differences, 15 acceptance differences, and 4 origin-only differences. Thus 65 parser/serialization failures and 4 origin-only failures. `diff_url/README.md` says both “excluded from the 69” and “4 of 69 are origin-only”; the former is false. [wpt-resumed.log](diff/wpt-resumed.log) begins: `tests 896 rust-fail 69 whatwg-url-fail 0 node-ada-fail 15`.

5. **Overstated: proof of equality everywhere outside the drive-letter exception.** The proof establishes equality for its hand-transcribed segment model and stated entry invariant. Its full-path theorem also applies `s_tail` to the file reference result, which deliberately removes leading empty segments. Therefore it does not establish equality to current WHATWG outside `bad`. The original detailed report mostly discloses this; the summary loses the qualification. CE5 is a real current-standard conformance difference even though it reflects old behavior.

## Independent reproduction and proof scope

The interrupted predecessor had already copied the proof and harnesses into this directory. I read that evidence and reran the copied proof, exhaustive path probe, WPT harness, URL examples in release/debug, and sanitizer anchor/noscript examples. Available memory was 160 GiB before these runs; no long fuzz campaigns were repeated.

- **Confirmed:** [verification-resumed.log](proof/verification-resumed.log) reports `verification results:: 33 verified, 0 errors`. The proof contains no `assume`, `admit`, or `external_body`. This verifies the supplied mathematical functions, not the executable crate or their correspondence to the whole URL Standard.
- **Confirmed:** [probe-resumed.log](proof/probe-resumed.log) reports `total=141325 mismatches=40929 unexplained_by_bad=0 bad_but_equal=2276`. Its reference deliberately includes leading-empty-segment collapse. The 2,276 equal final outputs despite `bad` correctly disprove using `bad` as an unconditional end-to-end divergence predicate.
- **Confirmed:** `step_lemma` assumes `wf(p), no_slash(seg)` and starts at `sp(p) + "/"`. `parse_path_agree` assumes `run_ok` and equates the implementation to `sp(if file { s_tail(s_run(...)) } else { s_run(...) })`. Byte-level input preprocessing, encoding, host states, and the actual Rust execution remain outside the proof. See [path_spec.rs](proof/path_spec.rs).
- **Confirmed:** CE1–CE4 and CE6 reproduce in the crate; CE5 also differs from today's reference. [repros-resumed.log](diff/repros-resumed.log) records the inputs, outputs, and reference outputs. CE1 retains `/C:/x` instead of `/x`; CE2 retains `/a/C:/x` instead of `/a/x`; CE3 produces `/a/C:x` instead of `/a/x`; CE4 panics in debug and produces the reported wrong release paths; CE6 retains `c|` instead of `c:`; CE5 collapses `file:////a` to `file:///a`.
- **Confirmed:** the debug log contains `assertion failed: self.serialization.as_bytes()[segment_start - 1] == b'/'` at url-2.5.8 `parser.rs:1321`. It also reproduces with `file:..` against `file:///w:/a:`. Therefore the differential report's “I could NOT reproduce a panic” needs “in the release build used for fuzzing.” Zero release panics says nothing about disabled debug assertions.
- **Confirmed, known classes:** [#1113](https://github.com/servo/rust-url/issues/1113) says: “When parsing `https://example.com/a/c:/..`, FireFox gives `https://example.com/a/` while the URL crate gives `https://example.com/a/c:/`.” [PR #1143](https://github.com/servo/rust-url/pull/1143) is titled “Fix panic joining a relative reference onto a file: URL with a drive-letter-shaped path segment (#1114)”. The panic and drive-letter failures should not be presented as new discoveries.

## Differential claims and novelty

**Confirmed:** all listed D1–D8, N1, N2, N3 and P1 representative behaviors reproduce. Their labels describe real version-2.5.8 differences from the pinned current reference. Known-issue pointers are retained in [known-issues.jsonl](known-issues.jsonl): #1140 caret encoding, #1160 empty path segments, #1126 file host removal, #1101 roundtrip, #1155/#1156 non-special backslashes, #1164 triple slashes, #1135 ASCII `xn--`, #1130/#1113 shortening, #889 pipe normalization. These reports establish prior awareness; an issue marked closed alone does not establish that a specific release contains a fix.

**Confirmed as stored-run counts, not independently rerun campaigns:** summing exactly seeds 11–18 and 21–44 gives 64,000,000 cases, 2,910,747 divergences, 30,062,315 reference successes, and 2,440,340 reference disagreements. Property seeds 101–104 total 8,000,000 cases and 406 violations. Source: `../vlm2_url/diff_url/data/fz_*.summary` and `pr_*.summary`. The reference-disagreement percentage needs its denominator: 3.81% of generated cases or 8.12% of reference successes, not simply “8% of fuzz cases.”

**Overstated:** “rust-url wrong in every [one of 3000] case” is stronger than the audit establishes. The predecessor reran all 3,000 minimized inputs and recorded `minimized 3000 still-divergent 3000` in [audit.log](diff/audit.log). This confirms disagreement, not an independent standard adjudication of every input. Representative families agree with the standard and WPT; the supplied report itself admits 93 unclassified cases and only spot checking. Novel rare classes and all root-cause assignments remain unverified.

**Confirmed with qualification:** all 406 stored property examples lose a host on reparse, but only 394 differ solely by host removal. Eleven also normalize a pipe drive letter; one also removes a dot segment after the tab/newline bug. “One bug” is too strong if intended to exclude interacting bugs. The summary's `file://host/C:/..` is not itself a direct parse-roundtrip counterexample: its first parse already loses the host. Use the reproduced join `/./C:/a` against `file://host/path`, whose first serialization is `file://host/C:/a` and whose reparse is `file:///C:/a`.

**N1: confirmed bug, wrong novelty.** PR #1159 above covers it. No matching drive-letter/control case appeared in either saved WPT snapshot; absence from these fixtures is not absence from upstream regression tests. [URL Standard basic parser](https://url.spec.whatwg.org/#concept-basic-url-parser): “Remove all ASCII tab or newline from input.”

**D6: confirmed bug, wrong novelty and wrong explanation.** WPT includes `non-special:opaque  ?hi`, expecting `non-special:opaque %20?hi`. The [opaque path state](https://url.spec.whatwg.org/#opaque-path-state) says: “If remaining starts with U+003F (?) or U+0023 (#), then append "%20" to url’s path.” This encodes the space immediately before the delimiter; it does not strip all trailing spaces, as the report describes. #1123 already mentions it.

**N2: confirmed bug; novelty unverifiable.** Searches for empty credentials, at-signs, and the exact input found no matching parser issue. Nearby #1148 concerns a setter and nonempty credentials. But the WPT fixture already has `{"input":"sc://@/","base":null,"failure":true}`. The copied release harness rejects that slash-terminated variant while accepting EOF-terminated `b://@`; thus the uncovered EOF variant is the narrower candidate. [Authority state](https://url.spec.whatwg.org/#authority-state): “If atSignSeen is true and buffer is the empty string, host-missing validation error, return failure.” No search can certify novelty. Search evidence: [n2-search-resumed.jsonl](n2-search-resumed.jsonl), [n2-exact-search.jsonl](n2-exact-search.jsonl), [credentials.jsonl](credentials.jsonl).

**N3: confirmed observed origin difference; deliberate intent unverifiable here.** The four origin-only WPT differences are separate from parsing. Do not infer intentional design merely from behavior without a maintainer/source rationale.

## Sanitizer claims

**Confirmed:** default ammonia is not a fixed point. [anchor-resumed.log](sanitize/anchor-resumed.log) gives `clean="<a rel=\"noopener noreferrer\"><a rel=\"noopener noreferrer\"></a><table></table></a>"` and flags `a:clean-not-idempotent`. The retained [heading.log](sanitize/heading.log) and [cr.log](sanitize/cr.log) reproduce heading restructuring and CR-to-LF normalization. These are mutation examples, not demonstrated default-configuration XSS. “Same family as DOMPurify” is a broad analogy; a specific shared exploit mechanism is unverified.

**Confirmed:** the raw-text allowlist preserves the noscript payload, and reparsing with scripting disabled exposes `onerror`. [noscript-resumed.log](sanitize/noscript-resumed.log) includes `clean="<noscript><img src=x onerror=alert(1)></noscript>"` and `c:event-attr:onerror@div-noscr`. The default case instead yields `&lt;img src=x onerror=alert(1)&gt;` with `viol=[]` in [default-noscript.log](sanitize/default-noscript.log). The copied RawText configuration adds multiple tags; this particular payload uses only noscript beyond the defaults.

**Partly documented; exact case unverifiable:** ammonia [PR #142](https://github.com/rust-ammonia/ammonia/pull/142), “Fix namespace switching bugs, release 3.1.2”, explicitly includes `noscript` among tags affected by dangerous custom allowlists. Its description says: “To solve this issue, check for unexpected namespace switches after cleanup.” Version 4.2.1 source retains that explanation near `src/lib.rs:2218`. This documents namespace switching, not the exact scripting-on versus scripting-off mismatch. A GitHub noscript search returned this PR, not an explicit contract declaring this latter behavior supported or safe. Do not call it either newly discovered or explicitly documented without more evidence. Saved response: [ammonia142.json](ammonia142.json), [noscript-search-resumed.jsonl](noscript-search-resumed.jsonl).

**Overstated default coverage:** the approximately 10M executions span all three configurations. Logs say `done Default execs=1174600`, `done Foreign execs=1191200`, and `done RawText execs=1134600`; exhaustive counts are respectively 5,399,042, 551,880, and 732,540. Default therefore accounts for 6,573,642 of these executions, not approximately 10M, and not all approximately 3.5M fuzz outputs. “No script-capable output found” remains a checker observation, not a safety theorem. The reported 6.5%, parse5 counts, 157-payload totals, and classifications of every rawtext/foreign result were not independently rerun; treat those exact claims as unverified beyond retained artifacts.

**Confirmed limitations:** the Kani log says `Kani unexpectedly panicked during compilation.` at `kani-compiler/src/intrinsics.rs:243`; no bounded proof follows. The empty deep-nesting output does not establish coverage or safety; the precise timeout history cannot be reconstructed from it alone. No real-browser execution evidence is supplied. False-positive C0 scheme checks are plausible: the URL preprocessing rule quoted above removes only tab/newline internally, not every C0 character; exhaustive classification of every flagged URL was not repeated.

## Review limits and recommended edits

Retain the concrete counterexamples and model proof. Replace novel-bug assertions with the prior reports above; narrow N2 to an unlocated EOF variant. Report 65 parser/serialization plus 4 origin failures. Describe the noscript result as a reproduced unsafe attribute after reparsing, requiring a tested activation step to demonstrate XSS. Keep campaign counts explicitly tied to configuration, build profile, and saved logs. Do not promote finite negative tests, a differential oracle, or a hand-transcribed model to a proof about the entire production implementation.
