# Independent layout and fragment-tree review
(authored by agents unless marked 🧑)

Reviewed `out/vlm3_servo/servo_fragment_tree/REPORT.md`, `servo_layout_algos/REPORT.md`, their proof files, the corresponding `SUMMARY.md` claims, and the relevant upstream source. Original files were not changed. Proofs ran from copies under `out/cx_servo/layout_work`. No Servo browser was built or run.

## Findings requiring correction

1. **Wrong:** fragment report says “Files (all verify” and includes `arc.rs`. The supplied file fails: `error: loop must have a `decreases` clause`, at its `sum` loop. The report correctly mentions this historical error but incorrectly presents the final file as passing. Evidence: `layout_work/servo_fragment_tree/arc.rs.log`. Immutable `Arc` children themselves are supported: the separate `find.rs` verifies using them.

2. **Overstated:** summary says `sov.rs` proves “the result contains its inputs, given no saturation”. Its only containment postcondition concerns the y axis, additionally requires `!scroll_container && vis_y`, and excludes the transform branch. On a non-visible axis the source deliberately preserves the border extent; a scroll container returns the border rectangle in this model. Thus the summary statement is false even without saturation. The component report's “on a visible axis” also exceeds the written postcondition: no x-axis containment theorem is supplied. Source [BoxFragment](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/fragment_tree/box_fragment.rs#L559) says `if overflow_style.y == ComputedOverflow::Visible` and separately `if overflow_style.x == ComputedOverflow::Visible`.

3. **Overstated:** summary says align-content “never divides by zero and leaves exactly 0 free space”. The zero-remainder theorem requires `free0.0 > 0`, `1 <= num_lines < 1000000`, and `a is Stretch || a is SpaceBetween`; SpaceBetween additionally needs two lines. The report acknowledges this narrower scope. The original source casts `num_lines as i32`; the model's million-line bound excludes cast overflow, but no source-level proof establishes that bound. Fallback proving `num_lines >= 2` alone does not prove this cast nonzero for arbitrary `usize` values. Source [flex layout](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/flexbox/layout.rs#L815): `AlignFlags::SPACE_AROUND => remaining_free_cross_space / num_lines as i32 / 2,`.

4. **Overstated:** summary says “the float fit check is sound, assuming non-negative object sizes”. `float_fits.rs` proves only collision rule 3, conditional on an opposing float existing. Rule 7 is false at the saturated boundary and has its own restricted proof. The component report accurately distinguishes these rules.

5. **Wrong as written:** layout report says “Saturation cannot flip the sign of the total (the sum of non-positive terms stays non-positive).” The parenthesized homogeneous-sign fact is true; the unrestricted statement is false. For M=1073741823, summing `[M,M,-M,-1]` with saturation yields -1, whereas the exact sum is M-1. This does not invalidate `freeze_step`: it only needs an unfrozen item whose sign matches the saturated total. Reproduction: `layout_work/numeric_repro.rs`, output `mixed-sign total: saturated=-1, exact=1073741822`.

6. **Wrong classification:** summary places table rounding under “Edge cases at extreme sizes only (above about 18M px)”. Three columns sharing one Au of extra width each receive zero Au with the actual `scale_by` rounding formula. This requires no extreme size. Source [table layout](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/table/layout.rs#L1073): `let extra_space_for_all_columns = extra_inline_size.scale_by(1.0 / columns.len() as f32);` followed by `*guess += extra_space_for_all_columns;`. [app_units 0.7.8](https://docs.rs/app_units/0.7.8/src/app_units/app_unit.rs.html) defines `let new_float = ((self.0 as f64) * factor as f64).round();`. Reproduction output: `table: extra=1 Au, distributed=0 Au`. This is a numeric reproduction, not proof of a rendered-page symptom.

7. **Overstated:** table report says the proportional sum is nonzero “exactly when a selected column exists with nonzero max-content”. `choose_rule` only states and maintains the forward implications `s1 > 0 ==> exists...` and `s3 > 0 ==> exists...`; the converse is not machine-proved. The code supports that converse mathematically under nonnegative inputs, but it should not be advertised as an explicit proved equivalence. No actual floating-point division or percent sum is verified.

8. **Overstated:** summary says “interior mutability (atomics, `Cell`, `OnceCell`, `ArcRefCell`) is unsupported”. The fragment report itself says “atomics need vstd atomic ghost-perm API; Cell needs PCell.” This is unported dependency work, not evidence that verification of interior mutability is impossible. Likewise “unmodelable” for `grid_info()` and “unsupported” for all FnOnce closures are unsupported generalizations from omitted work.

## Remaining fragment claims

- **Confirmed, model scope:** “Au = i32 saturating to +-(2^30-1)” and range/no-overflow proofs. Source [app_units](https://docs.rs/app_units/0.7.8/src/app_units/app_unit.rs.html) implements addition as `Au(self.0 + other.0).clamp()` and subtraction analogously. The proof assumes input bounds; the public Au type itself does not enforce them. Its source says “Please ensure that the values are between `MIN_AU` and `MAX_AU`.”
- **Confirmed, model scope:** translation/max_x/outer rectangle range, containing-block selection, `new_for_abs` and `new_for_abs_and_fixed`, terminating `size`/`size_from`, and clamped path-sum range. The `new_for_non_absolute_descendants` source method is not ported, so “new_for_*” is broader than coverage. Source [containing_block.rs](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/fragment_tree/containing_block.rs#L63) declares `pub(crate) fn new_for_non_absolute_descendants`.
- **Confirmed, numeric counterexample:** “x=5, w=MAX_AU, left=10, right=0” shrinks the maximum x under the modeled operations. The conditional `outer_contains_x` theorem verifies, requiring nonnegative sides and no size saturation. Independent Rust arithmetic outputs `outer_rect: old_right=1073741823, new_right=1073741818`.
- **Unverifiable end-to-end:** “reachable via CSS like `width:1e9px`”, wrong getBoundingClientRect/hit-test extents, and “likely benign”/low severity. Source confirms relevant callers and saturating Au conversion, but no complete style-to-layout-to-query reproduction establishes those effects. MAX_AU/60 is about 17.9 million px; “~16M px” is a loose estimate.
- **Confirmed, model scope:** `find` termination, clamped accumulation, and returned-level bound; `ok(n,d)` and `level+d <= 1000000` are assumptions. The result does not prove the returned node matches the target or is the first match. Real Servo tree construction, closure behavior, and depth invariant remain unproved, as the report acknowledges.
- **Confirmed, model scope:** `sofp` range, scroll-container identity, nonvisible y identity, visible y origin bound, and conditional bottom coverage. The extreme-span saturation explanation follows the code. “non-visible axis unchanged” is machine-proved only for y; x is supported by source inspection.
- **Confirmed omissions:** transforms, actual style types, ArcRefCell access, atomic caching, and closure postconditions are absent. The report's initial Arc blocker is superseded by its own round-two executable Arc traversal; unsupported interior mutation is a separate issue.

## Remaining layout claims

- **Confirmed, model scope:** shrink-to-fit bounds, malformed min/max behavior, identity in range, clamp functions, ordering preservation for `max`, and sufficient nonnegative-max preconditions for `union`. `SizeConstraint::new` only explicitly proves a Definite result's bounds, not all the identity/malformed properties implied by “obeys the same.” `definite_or_min` has no functional postcondition. “union preserves ordering only for non-negative sizes” should read “proved under nonnegative max-content assumptions”; some negative inputs also preserve it. The negative example `(-5,-5),(0,0)` does refute unconditional preservation.
- **Confirmed omissions:** `map(f)`, assignment/trait wrappers, LazySize, float computations are not proved. Replacing Au with a bounded i32 struct and closures with matches is visible in the code. Claims that practical sizes are always nonnegative are unverified caller invariants, not established properties of this type.
- **Confirmed, conditional:** allocation/fallback arithmetic and the positive-free-space Stretch/SpaceBetween loop theorem, with the bounds listed above. Negative integer division's exact quotient is intentionally absent from the postcondition. Historical explanations of enum equality and missing invariants are plausible but not independently established by the final files.
- **Confirmed, conditional:** rule-3 nonoverlap and rule-7 validity with `walls.inline_end < MAX_AU`. The negative-size issue is excluded by the actual proof precondition. Independent numeric rule-7 witness uses candidate=M-1 and size=2: `rule7: fits=true, exact_right=1073741824`. The source check is `candidate_inline_start + object.size.inline > walls.inline_end` ([float.rs](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/flow/float.rs#L583)).
- **Overstated reachability condition:** “only with two absurd (~10^7 px) sizes” is not necessary for the arithmetic failure: the second float can be 2 Au when the first candidate is M-1. A huge context/candidate is needed; two huge float sizes are not. The source assignment `inline_end: inline_start + containing_block_for_children.size.inline` is present in [same_formatting_context_block.rs](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/flow/same_formatting_context_block.rs#L274). CSS reachability and “no real-page impact” remain unverified.
- **Confirmed, conditional:** table blend's exact sum, nonnegative widths, safe remainder arithmetic, and first-column correction for nonempty vectors of bounded nonnegative raw widths. Float-to-raw production and source debug-assert deviation bounds are excluded. The theorem does not establish that the whole original function cannot panic at its additional debug assertion.
- **Confirmed progress lemma; overstated whole-loop proof:** `freeze_step` preserves frozen flags and freezes a previously unfrozen item whenever total != 0. The actual flex outer loop is absent, so its termination is an inference from this lemma plus source inspection, not directly verified. At most n *nonreturning* iterations follows; a final returning iteration may follow. The statement “termination relies on ... not producing NaN” is unestablished: `scale_by` converts its rounded/clamped float to i32, so the modeled progress reasoning does not itself require that hypothesis. No complete float-path proof was attempted.
- **Confirmed, spec model:** skew/split preserve BST/key sets; insert preserves order and inserts/replaces keys; find/find_next return the appropriate predecessor/successor or None. Shapes match source. The sentinel lemma checks only the tree constructed from the two sentinels, not every reachable mutable context. Extending it through insert follows from the proved preservation theorem; `set_range`, source payloads and construction are not verified. Consequently “its unwraps cannot panic” is conditional source reasoning, not an executable Rust theorem. The actual caller explicitly handles `ceiling == MAX_AU` before `find_next(...).unwrap()` ([float.rs](https://github.com/servo/servo/blob/d275164b2bf624ee5844b22522d10c81b8f606ab/components/layout/flow/float.rs#L106)).
- **Confirmed limitations:** no AA balance/height theorem, no asymptotic complexity theorem, no `set_range`, and no executable tree verification.
- **Confirmed, model scope:** extra-width rule result is 1..6, selected-rule existence properties, positive integer counts, and guarded colspan subtraction. The model assumes nonempty columns/nonnegative max-content and replaces percentages with booleans. The report's `span >= 1` assumption is expressly unproved. `colspan_ratio_guard` does not prove any floating-point division.
- **Confirmed source observation; unverified bound:** extra-width distribution has no remainder repair. “up to about one Au per column” is not a universal established bound: proportional factors involve f32 rounding and saturating total max-content, both excluded from these proofs. No caller tolerance or rendered effect was checked.

## Historical and broad claims

**Unverifiable from retained artifacts:** elapsed effort, number of development attempts, exact historical failure messages except the retained rule-7 failure and present Arc error, and explanations of the solver's internal reason for each failure. Final proofs alone cannot authenticate this history. The missing-code/omission inventories are confirmed by the supplied proof files; statements declaring features inherently unsupported are not thereby established.

The summary's “round 1's next steps are all done” is **overstated** for these components: the fragment report still lists closure postconditions, atomic caching and the real tree-depth invariant under “Remaining”; the layout report leaves balancing, set_range and float arithmetic undone. “Most proofs are on numeric or structural skeletons; floats and interior mutability were left out” is **confirmed** for this review scope. Browser impact/severity judgments remain **unverifiable**, not disproved.

**Overstated recurring-friction claim:** “structural recursion over `Vec<Arc<T>>` needs a ghost fuel parameter”. This experiment supplies such a parameter and verifies with it; it does not show that fuel is the only possible proof technique. `frag.rs` separately verifies structural descent through `Seq<Frag>`. The supportable statement is that this executable `Vec<Arc<Node>>` proof uses a caller-supplied depth bound. Likewise reported shift-expression failures and missing enum-equality specifications describe these attempts, not general impossibility results.
