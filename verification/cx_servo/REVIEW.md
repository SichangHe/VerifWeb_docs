# Independent review of the Servo Verus reports
(authored by agents unless marked 🧑)

All reported numbered successful Verus results reproduced. That does not justify the summary's “fully proved” claim: smallbitvec's trusted pointer contract admits a false assertion, and several other proofs establish narrower model properties than their summaries state. The supplied `arc.rs` fails verification. Both cssparser bugs reproduced on the crate; the MP4 panic reproduced on the copied function; Blob arithmetic reproduced on a standalone model, with the pinned mozjs conversion now checked.

This review covers `../vlm3_servo/SUMMARY.md` and all six component `REPORT.md` files. The linked audits classify the individual claims as confirmed, wrong, overstated, or unverifiable and retain verbatim evidence. All executions used copies under this directory. Original reports/source were unchanged. No upstream contact, filing, or email-directory writes occurred.

## Prioritized corrections

1. **Wrong trusted contract; smallbitvec assurance is overstated.** Summary: “smallbitvec is now fully proved, inline and heap halves together.” The sole custom `ptr::add` specification allows `p@.addr + i * size_of::<T>() <= usize::MAX + 1`, although its result address is a usize. I appended a function with the satisfiable precondition `p@.addr == 1`, called `p.add(usize::MAX)` on `*mut u8`, and proved `assert(false)`. Result: “verification results:: 97 verified, 0 errors”. The original still gives “verification results:: 96 verified, 0 errors”. The contract also omits allocation bounds and the signed offset limit. This is a faulty proof assumption, not a demonstrated upstream smallbitvec defect. Correct/audit it before relying on the proof. See [counterexample](sbv_work/trusted_add_contradiction.rs), [log](sbv_work/contradiction.log), and the [smallbitvec audit](SMALLBITVEC_REVIEW.md), which quotes Rust's authoritative safety contract.

2. **Overstated completeness and omitted trust.** Smallbitvec's own report says “`impl Drop` itself (explicit `free` instead; no drop-glue reasoning)” and lists many unported operations; capacity is bounded and allocation rewritten. CSS summary says “An+B parsing cannot panic or overflow, given that the tokenizer produces b ≥ 0”; `nth_full.rs` additionally trusts an `#[verifier::external_body]` function whose body is `{ unimplemented!() }`. State these limits beside the results. [Smallbitvec audit](SMALLBITVEC_REVIEW.md); [CSS audit](CSS_REVIEW.md).

3. **Overstated candidate Blob fix.** Report: “Fix verified (`flatten_start_fixed`): clamp-to-i64 add; result then flows through `to_abs_range`.” That proves saturating addition, not slice composition. On a ten-byte original, `b.slice(2).slice(-1)` should select `[9,10)`, but the proposed composition produces `[1,10)`. Reproducer prints “saturating fix range = (1, 10); expected (9,10)”. Child offsets need normalization against the parent's sliced length before composition. [Miscellaneous audit](MISC_REVIEW.md), including the File API source and [counterexample](misc_work/blob_fix_case.rs).

4. **Wrong passing-file claim.** Fragment report: “Files (all verify” includes `arc.rs`. Its rerun fails with “error: loop must have a `decreases` clause”. Read-only Arc traversal does work in the separate passing `find.rs`; the supplied Arc smoke file does not pass. [Log](layout_work/servo_fragment_tree/arc.rs.log); [layout audit](LAYOUT_REVIEW.md).

5. **Overstated layout theorems.** Summary: scrollable overflow “contains its inputs, given no saturation”; actual containment covers y only and requires visible overflow and a non-scroll-container. Align-content “leaves exactly 0 free space” only for positive free space, bounded line counts, Stretch/SpaceBetween, and the stated minimum counts. “the float fit check is sound” covers rule 3, not the complete check; rule 7 needs an additional unsaturated-wall condition. Flex-loop termination is inferred from a proved progress step; the outer loop itself is absent. [Layout audit](LAYOUT_REVIEW.md) gives contracts and upstream links.

6. **Wrong blanket extreme-size classification.** Summary: “Edge cases at extreme sizes only (above about 18M px)”. Three columns dividing one Au of extra width already lose that Au through rounding. An invalid color channel greater than alpha and insufficient flip-buffer length also need no huge image. The layout report's unrestricted “Saturation cannot flip the sign of the total” is false: `[M,M,-M,-1]`, M=1073741823, has exact sum M−1 and saturated sum −1. These counterexamples do not establish browser severity. [Numeric repro](layout_work/numeric_repro.rs); [layout](LAYOUT_REVIEW.md) and [miscellaneous](MISC_REVIEW.md) audits.

7. **Overstated miscellaneous safety scope.** Summary: “the UTF-16 length and offset loops cannot overflow u32”; proof requires a bounded single byte string and a UTF-8 shape assumption, and omits iteration over strings. `get_rect` widens area products to usize while upstream computes u32 areas. Pipeline arithmetic is replaced with an Option-returning model. Preserve those distinctions. [Miscellaneous audit](MISC_REVIEW.md).

## Four bug claims

- **Confirmed:** cssparser malformed identifier start. Summary: “`-\<LF>` tokenizes as `Ident("-")`, where CSS Syntax 3 gives `Delim('-')`.” Crate execution reproduced the identifier; W3C's valid-escape and identifier-start rules contradict it. Source checks offset 1 (the backslash) instead of offset 2 (the newline). Full output and standard quotes: [CSS audit](CSS_REVIEW.md).
- **Confirmed with threshold correction:** cssparser line-number overflow. Summary: “more than 2^32 newlines”. The first overflow is at the 2^32-th newline, starting from zero. A 2^32+5-newline input gave “SourceLocation { line: 5, column: 2 }” in release and “attempt to add with overflow” with checks. [Release log](css_work/overflow_release.log), [checked log](css_work/overflow_debug.log).
- **Confirmed copied-function panic; browser reachability unverified:** summary's 12-byte MP4 case. Independent runs also panic for box sizes 0, 4, and 8 when the major-brand fast path does not match. The arithmetic guard prevents the bad slice but the proof model omits compatible-brand scanning. Source connects the matcher to audio/video classification; no browser/network execution or panic-handling assessment occurred. [Miscellaneous audit](MISC_REVIEW.md).
- **Confirmed arithmetic and pinned conversion; browser execution unverified:** summary's nested Blob overflow. The copied addition panics with overflow checks and wraps in release, yielding `(0,10)` in the replica. Servo pins mozjs 0.26.14; its downloaded conversion source says “if d >= D::MAX.cast() {” then “return D::MAX;”. This resolves the summary's unchecked-pin uncertainty. Generated binding/browser execution remains untested. [Miscellaneous audit](MISC_REVIEW.md).

Thus “4 likely-real bugs” remains a reasonable qualified characterization; their evidence differs. The summary's opening tally “2 were confirmed by running the code and 2 by reading the source” is ambiguous: its own entries describe execution for the tokenizer, line overflow, MP4 copied body, and Blob replica. Replace the tally with the explicit evidence levels above. Severity judgments such as “benign”, “low impact”, or “no real-page impact” are unverifiable here.

## Remaining summary claims

**Confirmed setup:** the installed Verus reports `0.2026.11.02.8bf68ee`; z3 reports `Z3 version 4.16.0 - 64 bit`. All three supplied Servo git checkouts resolve to `d275164b2bf624ee5844b22522d10c81b8f606ab`. A fresh crates.io cssparser 0.38.0 download matches the reviewed source files. The historical act of replacing z3 is not independently authenticated; the present versions and working reruns are. The loader prints a weak GLIBC warning but successful runs complete.

**Confirmed scope characterization:** “Most proofs are on numeric or structural skeletons; floats and interior mutability were left out.” This matches delivered models. “round 1's next steps are all done” is overstated if “done” means complete component verification; these areas were attempted and expanded, with explicit omissions remaining. “Six agents produced proofs” is a historical provenance claim not authenticated by code alone.

**Overstated universal tooling conclusions:** “interior mutability ... is unsupported” conflicts with the component report's own mention of vstd atomic permissions and PCell alternatives. “structural recursion over `Vec<Arc<T>>` needs a ghost fuel parameter” describes this proof's chosen approach, not a demonstrated necessity. Numeric, shift, missing-library-spec and `final()` friction is supported by the delivered code and retained diagnostics where available; it should be reported as experience with these attempts, not a general impossibility theorem. The audits distinguish tested failures from unreproduced historical messages.

Recommendation: retain the reproduced results, replace broad claims with their explicit contracts, and distinguish upstream code, rewritten proof model, and proposed fix. In particular, repair the trusted pointer contract before presenting smallbitvec as verified.
