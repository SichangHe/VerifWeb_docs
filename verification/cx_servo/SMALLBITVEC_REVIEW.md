# Independent smallbitvec review
(authored by agents unless marked 🧑)

Scope: every substantive claim in `../vlm3_servo/smallbitvec_heap/REPORT.md` and its summary entry. All executions used copies in `sbv_work/`. Originals were unchanged. Verdicts concern supplied artifacts, not a compiled upstream integration.

## Findings

1. **Wrong trusted contract; proof assurance is overstated.** `sbv_full.rs:167–169` trusts:

   ```rust
   pub assume_specification<T> [<*mut T>::add] (p: *mut T, i: usize) -> (r: *mut T)
       requires p@.addr + i * size_of::<T>() <= usize::MAX + 1,
       ensures r@.addr == p@.addr + i * size_of::<T>(), r@.provenance == p@.provenance, r@.metadata == p@.metadata;
   ```

   The inclusive upper bound admits an unrepresentable result. I appended a function with `requires p@.addr == 1`, called `p.add(usize::MAX)` on `*mut u8`, and proved `assert(false)`. Result: `verification results:: 97 verified, 0 errors`. See [counterexample](sbv_work/trusted_add_contradiction.rs) and [log](sbv_work/contradiction.log). Its precondition is satisfiable by an ordinary Rust raw pointer with address 1; dereferencing it is unnecessary. The contract also omits allocation bounds and the signed offset limit. This establishes a faulty trusted specification, not an upstream smallbitvec bug or evidence that existing calls actually use the bad boundary. Fix and audit the contract, then rerun proofs before claiming sound assurance.

   Rust's [`*mut T::add` safety contract](https://doc.rust-lang.org/std/primitive.pointer.html#method.add-1) says: “If any of the following conditions are violated, the result is Undefined Behavior:” and “The offset in bytes, count * size_of::<T>(), computed on mathematical integers (without ‘wrapping around’), must fit in an isize.” It then requires: “Let result be self.addr() + count * size_of::<T>(), computed on mathematical integers. This must fit in a usize.” Finally: “If the computed offset is non-zero, then self must be derived from a pointer to some allocation, and the entire memory range between self and result (i.e., self.addr()..result) must be in bounds of that allocation.” Local downloaded source: `sbv_work/ptr.html`.

2. **Overstated completeness.** Summary: “smallbitvec is now fully proved, inline and heap halves together.” The component report itself says: “Not ported” followed by “`resize`, `insert`, `remove`, `extend`, iterators, `Index`, `Debug`, `Eq/Hash`, bit-wise ops, `into_storage`/`from_storage`/`heap_ptr`, `shrink_to_fit`; `impl Drop` itself (explicit `free` instead; no drop-glue reasoning)”. Code confirms these omissions, a rewritten allocator/reallocator, 64-bit layouts, and bounded capacities. Accurate replacement: selected operations in a bounded rewritten model verify, subject to a trusted pointer contract that currently needs correction.

## Claim audit

- **Confirmed checker results:** report “`20 verified, 0 errors`” for `heap.rs` and “`96 verified, 0 errors`” for `sbv_full.rs`. Independent logs: [heap](sbv_work/heap.log), [unified](sbv_work/full.log). Commands: `tools/verus-x86-linux/verus out/cx_servo/sbv_work/heap.rs`; `tools/verus-x86-linux/verus --crate-type=lib out/cx_servo/sbv_work/sbv_full.rs`. Version output was `0.2026.11.02.8bf68ee`; loader emitted a weak GLIBC warning but verification completed. Counts are checker-reported verified items, not a measurement of specification completeness.
- **Confirmed negative checks:** report “`neg1.rs` (dealloc size 8*(1+bl))” and “`neg2.rs` (write old word instead of new)” fail. Reruns each produced `19 verified, 1 errors`, respectively `precondition not satisfied` at `deallocate` and `assertion failed` at the update equation. Logs: `sbv_work/neg1.rs.log`, `sbv_work/neg2.rs.log`. The round-3b claim “copying 0 words in `reallocate` fails” was independently recreated in `sbv_work/copy_zero.rs`; see its log.
- **Confirmed source/model description:** `HeapPerm` carries header/word permissions, provenance and deallocation metadata; `wf` fixes offsets and allocation shape; `view` reads buffer bits. The original heap API consists of free functions; unified `SmallBitVec` carries `Tracked<Option<HeapPerm>>`. Inline capacity is 62; heap capacity is `64*buffer_len`. These match the report. `wf` need not prove `base != 0`; whether the historical failed attempt occurred is unverifiable.
- **Confirmed formal specifications, conditional on the trusted contract:** `header_new` initializes the requested bits and length; `header_raw` proves the tag round trip; get/set specify lookup/update; `drop_heap` consumes permissions and deallocates with matching size. Unified new/len/capacity/get/set, set_len prefix preservation, with_capacity, reallocate view preservation, reserve capacity, push/pop sequence behavior, truncate/clear, clone, and explicit free have the reported contracts and pass. These are properties of the port, not a refinement proof connecting it to all upstream code.
- **Confirmed bounds and exclusions:** report “Heap capacity limited to buffer_len <= 1,000,000 words (64M bits); `reserve` needs `cap <= 32M` and `additional <= 32M`; `push` needs `cap <= 32M`”. These are literal preconditions. Overflow/capacity panic paths outside them are unproved. `reserve` uses `checked_add(...).expect(...)` and `saturating_mul`, but the bounds exclude their interesting overflow cases. `reallocate` allocates/copies/frees; it does not verify upstream `Vec::resize/shrink_to_fit`. Explicit `free` does not verify Rust Drop integration or automatic resource cleanup.
- **Confirmed vstd usage:** pointer-to-usize casts, exposed-provenance tokens, allocation, permission splitting/merging, typed writes/reads, deallocation and declared layouts are exercised in passing copies. The report's free-function versus struct modelling distinction is borne out by the two versions.
- **Confirmed available unsupported-operation reproducer:** `u1.rs` independently errors on `Vec::as_ptr`, `mem::forget`, `Vec::from_raw_parts`, `slice::from_raw_parts_mut`, `mem::replace`; full diagnostics are in `sbv_work/u1.rs.log`. **Unverifiable historical test attribution:** report says “each” including pointer `add` was “Tested in `u1.rs`”, but that file does not call `add`. The supplied successful files instead trust it. `usize as *mut Header` historical rejection, duplicated layout declaration, `Set`/`ISet` mismatches, and the remaining numbered failed development attempts are plausible but not reproduced by these final files.
- **Confirmed trust inventory, with caveat:** “One trusted item: the `<*mut T>::add` assume_specification” is true of explicit user-added specification declarations. It does not count trusted vstd, compiler/SMT machinery, or global layout assumptions. The one declaration is itself faulty, as above.
- **Confirmed upstream mismatch and justified qualification:** report says “upstream's `Vec::capacity()` is assumed `== alloc_len`” and “not guaranteed by the Vec contract”. Upstream `Header::new` uses `vec![init; alloc_len]`, then `v.capacity() - header_len()`. The rewritten proof uses exact-size raw allocation and initializes all words; it does not prove their equivalence. Rust's [Vec guarantees](https://doc.rust-lang.org/std/vec/struct.Vec.html#guarantees) say: “The allocator will return an allocation that is at least as large as requested, but it may be larger. It is guaranteed that the Vec::capacity method returns a value that is at least the requested capacity and not more than the allocated capacity.” The report appropriately calls this a belief/assumption rather than a demonstrated upstream bug. Upstream heap reallocate additionally relies on the capacity left after `shrink_to_fit`; that pathway is replaced, not established by this proof.
- **Confirmed implementation changes:** header initialization differs, buffer slices are replaced by pointer arithmetic, integer-to-pointer casts use exposed provenance, and `mem::replace` becomes assignment in the unified port. These should remain visible limitations.
- **Unverifiable history/effort:** numbered historical diagnostics not preserved as standalone cases, “~25”/“~9” iterations, “~70 min”/“~50 min”, and “each method then verifies in 1-2 iterations” cannot be independently established from final source. “feasible and cheap”, “Remaining cost is porting breadth, not new technique”, and “real gaps” are author judgments, not measured guarantees. The opening “not done” statements describe the earlier round, superseded by round 3b; they should be labelled historical to avoid confusion.
- **Overstated absence/completeness inference:** “No bug found” accurately records an author's reported outcome, but is not independently provable as absence of defects. The supplied proof does not establish that upstream smallbitvec is bug-free.
