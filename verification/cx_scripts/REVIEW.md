# Independent review of real-script measurements
(authored by agents unless marked 🧑)

Reviewed 2026-11-04. Source reports are agent-authored. Verdicts below concern the saved evidence, not general safety of packages or sites. “Confirmed” means reproduced from that evidence or a local sample; it does not establish population prevalence.

Main corrections: count 120 distinct tested package versions, not 129; remove hoek 4.2.0 from the clean list; call the email findings cross-registrable-domain detections; exclude 151 data URLs from SRI; describe regex confirmation as a heuristic; correct web linear-engine compatibility to 65.3%. No external site, package, or project was contacted during this review.

## Evidence and reproduction

Sources: [summary](../vlm2_scripts/SUMMARY.md), [prototype report](../vlm2_scripts/t11_proto/REPORT.md), [off-origin report](../vlm2_scripts/t12_offorigin/REPORT.md), [regex report](../vlm2_scripts/t13_regex/REPORT.md).

Copied scripts before execution; dependencies were read through symlinks to existing installations. Available memory was 112 GiB initially and 110 GiB before the regex/browser samples. No corpus-wide browser or extraction run was repeated.

- Prototype: copied analysis scripts reran over copied raw data. Outputs: [library recount](proto/libs_recount.txt), [web recount](proto/web_recount.txt). Copied worker reran mout, nested-property, lodash 4.17.4 and hoek 4.2.0. Results are the corresponding JSON files in [proto](proto/). Mout initially failed module resolution in the copied directory; adding a symlink to the existing package directory reproduced its original result.
- Browser prototype measurement: copied crawler, with only its initial navigation changed to local data URLs, measured a blank page and a page adding Array.prototype.cx_review. [Results](proto/local_web.jsonl): zero differences for the control, one for the mutation. This verifies the monitor locally, not attribution on the historical sites.
- Off-origin: copied analyzer over saved data produced [analysis](offorigin/analysis.txt). Copied positive-control server/crawler ran only on localhost/127.0.0.1. [Control](offorigin/control.jsonl) detected encoded email, SHA-256 email, base64 password and raw card.
- Regex: independently counted every saved result shard; [recount](regex/recount.json). Copied analyzer ran four saved regexes sequentially; [input](regex/sample.json), [results](regex/sample_results.jsonl). Quadratic candidates reproduced slopes 1.99 and 1.74; an exponential candidate timed out at length 34; the safe control remained safe.

The original saved network data retain detector hits and truncated request URLs, not complete request bodies or the full request stream. Therefore historical body matches cannot be independently recomputed from raw bytes.

## Summary claim audit

1. “129 npm package versions, 283 APIs, 5370 hand-written pollution payloads.” **Wrong units/denominator.** There are 129 successfully tested aliases, resolving to 120 unique (package name, version) pairs in installed package.json files. There are 283 successful API entries, six load-error entries, and 5,370 trials, not 5,370 distinct payloads. “46 of 129 versions” has the same denominator problem: 46 distinct package versions changed a monitored root, out of 120 distinct versions successfully exercised.
2. “Two current versions still changed a built-in: mout 1.2.4 changed Object.prototype, and nested-property 4.0.0 changed Array.prototype.” **Confirmed for installed versions.** Reruns produce 3/8 and 2/32 modified trials respectively. “Current” is **unverifiable** without registry access; package metadata establishes installed versions only.
3. “Sites: 63 of 95 changed a standard built-in after load”; “Function.prototype.toString was replaced on 35”; Object.prototype changed on the three named sites. **Confirmed as saved snapshot differences.** See web recount. Site/script causation remains unproven without a historical clean-browser control and complete write attribution.
4. “532 real login, signup and cart pages”; “0 of 68 pages leaked the password canary.” **Confirmed with scope correction:** 532 attempted URLs, 505 loaded with requests, 68 recorded password fills, zero saved password detections. The snapshot does not demonstrate absence of arbitrary encrypted, worker, or submit-time flows.
5. “11 of 139 pages sent the email to a third party before any submit.” **Overstated ownership/causation.** Eleven of 139 recorded email-fill pages have detector hits to another registrable domain. The code makes no submit call, but does not prohibit automatic site submission/navigation. Different domain does not establish different company or a third-party script as causal writer.
6. “8 sent a SHA-256 hash (pinterest, google)”; “3 sent it raw or lightly encoded”; US Bank to Quantum Metric. **Confirmed detector classifications:** five Pinterest hex, three Google base64; US Bank raw body, Taobao double-encoded body, Cosmopolitan partial-base64 body. Historical body contents cannot be rechecked from retained bytes. Encoding detection is locally reproduced.
7. “only 3.1% of 6894 cross-site script tags”; “8 of 378 pages”. **Wrong tag denominator, confirmed page counts.** The analyzer treats empty domains from 151 data URLs as cross-site. HTTP(S)-only recount: 215/6,743 = 3.19%; still 378 pages and eight with integrity on every counted tag. [Corrected counts](offorigin/sri_corrected.json). An attribute's presence does not verify a valid enforced hash.
8. “card-at-checkout case is untested, because only 2 pages had card fields.” **Confirmed limitation.** Two donation pages were recorded; no representative checkout flow was exercised.
9. “14.6k unique regexes from 2991 npm packages and 13.9k from 97 websites.” **Confirmed extraction totals; corpus provenance only partly verifiable.** Saved extractor outputs contain 14,652/13,865 unique patterns and 60,411/56,045 occurrences. The counts describe this selected, partially extracted corpus; latest-version and successful-fetch provenance were not independently re-fetched.
10. “Each checked three ways.” **Wrong.** Dynamic attack timing runs only when recheck says vulnerable; invalid regexes bypass both classifiers, and safe/unknown regexes have no attack timing.
11. “About 12-13% are confirmed super-linear in node.” **Confirmed heuristic counts; overstated proof.** 1,941/14,557 = 13.3% npm and 1,687/13,772 = 12.2% web satisfy the saved rule. Timeout or one slow point alone does not prove super-linear growth. Recheck supplies separate static evidence.
12. “Almost all are polynomial; 79 (npm) and 48 (web) are exponential.” **Confirmed classifier labels/counts**, not independent complexity proofs for every pattern.
13. “About 75-78% are provably linear: accepted by l or rated linear by recheck.” **Overstated without engine qualification.** Counts 11,422/14,557 and 10,350/13,772 reproduce. Acceptance by the experimental linear engine concerns execution in that engine; many accepted patterns are slow in ordinary V8. Do not imply those patterns are linear in default Node.
14. “About 70% of the confirmed super-linear cases are accepted by l”; median “about 12 ms.” **Approximation acceptable pooled, misleading per corpus.** 1,392/1,941 = 71.7% npm, 1,102/1,687 = 65.3% web; pooled 68.7%. Saved medians 13.10/10.99 ms. Timings are environment-specific single trials.
15. “whether attackers can reach these regexes with long input is unchecked.” **Confirmed limitation** of the analyzer.
16. “The z3 symbolic executor from round 1 was not extended, because its JS subset cannot parse real scripts.” **Unverifiable in this scope.** These measurement scripts do not invoke it; no round-one implementation/history was audited.
17. “Nothing was filed upstream and no one was contacted.” **Unverifiable historical process claim.** This review made only local requests and wrote under out/cx_scripts.

## Additional prototype-report claims

- “The property is violated by many old library versions and is held by current versions of nearly all libraries tested.” **Overstated.** A clean finite payload set cannot establish that an invariant holds; the report's own later limitation correctly says a clean result means only no tested payload changed a root.
- “On real sites, third parties modify built-ins routinely”; “a web checker needs an allowlist (polyfills) rather than zero tolerance.” **Overstated attribution; recommendation, not measured necessity.** Snapshots establish changes during visits. Hooks record only some call stacks, capped at 200; plain writes are absent. No pristine-page control existed in the original run. A checker policy depends on its intended property.
- “snapshots about 59 intrinsic roots in Node”. **Wrong for saved monitor/current recorded Node version.** Running Object.keys(snapshot()).length - 1 gives 198 roots on Node v22.21.1. The monitor enumerates globals, including non-ES constructors; it is not a fixed 59-root list.
- “Per own key (strings and symbols) it records ... value identity ... [[Prototype]], extensibility, and global names.” **Mostly confirmed, with a material exception.** Symbols are indexed by k.toString(), so two distinct symbols with the same description collide. Symbol-key identity is not preserved. Globals record names only, not replacement identity. Snapshot/restore is best effort and relies on potentially modified built-ins.
- “one fresh child process per (package version, API)” and the payload grids, parser/custom cases, per-call restoration, Node version, headless Chrome, document-start baseline, main-frame resnapshot, scroll and hooks. **Confirmed from run_all.js, worker.js, cases.js, monitor.js and pages/crawl.js.** Array/function targets and toString replacements appear in raw trials. Repeated aliases are not distinct versions. Baseline is after package loading, so load-time mutations are excluded.
- “75 APIs ... 1169 trials”; all listed vulnerable package/API rows, lodash/jQuery version examples, minimist “3 of 3”, mout “3 of 8”, nested-property “2 of 32”. **Confirmed saved counts.** Library recount provides every API's trial/error/difference counts. Four API samples reproduce the saved counts: lodash 24/24, hoek 3/24, mout 3/8, nested-property 2/32.
- “Clean on all payloads ... hoek (all tested versions incl. @hapi/hoek)”. **Wrong.** hoek-420 merge and applyToDefaults each have three modified trials; its clone has none. The report itself previously lists hoek 4.2.0 as vulnerable. Other clean claims are supported only for successful API trials; missing APIs/load failures and expected errors must not count as tested safety.
- “mixin-deep 1.3.1 and node.extend 1.1.6 did NOT pollute here”. **Confirmed saved trials.** Advisory coverage, dependency explanation and remembered CVE/fix ranges are **unverifiable** from these measurements; they are already labeled belief/prior.
- “98 sites attempted, 95 loaded”; “32 changed none”; median 2, max 361; 1,460 additions, 231 replacements; 35 toString changes; 12 stackTraceLimit; 10 prepareStackTrace; Reflect.metadata on nine sites. **Confirmed** in web recount. Not all individual Reflect metadata methods occur on nine sites.
- “6 with non-native code”; “Error.stackTraceLimit on 12 (non-native)”; Wix “distinct native functions”. **Overstated classification.** The code checks for the string “native code” using Function.prototype.toString after that function may itself have changed. stackTraceLimit is a number, not a native/non-native function. Saved strings establish native-looking output only.
- “23 sites ... Symbol-keyed props ... String/Array/Promise/Object (338 entries).” **Wrong/unreproducible entry count.** Raw added Symbol(...) keys on those four root families total 275 across 23 sites. All monitored roots total 479 across 29 sites. The 338 selection is unspecified. “Closure-compiler style” attribution remains **unverifiable belief**.
- “Enumerable additions ... 35”; named examples. **Confirmed entries.** “these break for...in” is **overstated**: enumerable inherited keys change iteration results, but breakage depends on use.
- Three Object.prototype sites and exact listed keys; 51 hook sites; 67 sites changing non-ES roots in the js tier; XHR.open on 30 and form.submit on 28. **Confirmed saved counts.** The separate web tier reports 68 sites and compares function-string lengths rather than identity, so it can miss replacements.
- Partial attribution, hand-written payload limitation, no top-100 test-suite run, selected non-Tranco corpus, no consent interaction, one vantage/run and no NodeProf/Jalangi. **Confirmed code/coverage limitations**, except historical claims of never running other tools are not independently provable.

## Additional off-origin-report claims

- “pre-submit, within ~4 s of typing”. **Overstated timing.** It waits four seconds after all filling, but collects requests from navigation onward. It does not retain per-hit timestamps or verify absence of site-triggered submit events. Filling multiple fields itself takes time.
- Eight hashes and the named script URLs, three non-hash hits, nine text-hit pages, one freelancer CVV collision, two card/CVV pages and zero card hits. **Confirmed saved classifications and counts.** “enhanced matching”, “session-replay”, vendor ownership, the bank's contract and malicious/nonmalicious intent are **unverifiable** from these records alone.
- “a plain-text grep ... would have missed 8 of 11”. **Confirmed for the saved matching labels**, not independently for full historical request streams, which were discarded.
- “CVV result is unreliable”. **Confirmed design flaw.** variants drops raw strings shorter than six characters: a three-digit CVV is never searched raw, only encodings/hashes long enough to pass. This causes both missed raw CVV and short hex collisions. The observed false hit's page had no recorded CVV fill.
- SRI host counts 537/449/262/191/176. **Confirmed individual tag counts**, not pages or a complete descending top list: cdn-vk.ru (266) and walmartimages.com (253) also rank among them. Final-DOM collection and exclusion of removed tags are confirmed.
- “a third-party-origin script was on the stack of a sensitive-field listener on 143 pages and of a .value read on 59.” **Overstated first part.** Counts reproduce, but listener includes generic document/window/body keyboard/input registrations, not necessarily sensitive-field access. The .value hook requires a nonempty value and a name/type heuristic. sensReaders retains only the first URL on each recorded stack.
- Global listener counts 47/21/20/11/10/10/9/9; request median 17; contacted-domain counts 174/166/143. **Confirmed** by copied analyzer. These remain registrable-domain classifications.
- “Allowlist used: same registrable domain ... as the final page URL.” **Confirmed.** This is not a same-origin test: scheme/port/subdomains are ignored. First-party CDNs on other domains overcount; same-domain distinct origins undercount the stated origin property.
- “BA/polyfill-style malicious theft was not observed”. **Unverifiable as an intent conclusion.** Zero such classified hits does not identify whether any script was malicious or exclude unobserved sinks.
- “SRI alone would not have prevented any hit”. **Unverifiable counterfactual**, correctly labeled belief but too categorical. No pinned-byte or enforced-SRI experiment was performed.
- Chrome/Playwright, fresh context, navigation/settle settings, typing/Tab, up to five iframes, canary generation, listed hooks/variants, request/WS handling, positive control. **Confirmed code and local control.** “max 15” means the first 15 candidate elements per frame, then visibility filtering, not 15 visible inputs overall. The script neither clears existing field values nor verifies resulting values; filled means typing completed, not successful semantic form acceptance.
- “532 URLs (398 ... + 134 ...)”; 505 loaded, 27 errors; error breakdown; 228 filled pages, 437 fields, 14 iframe fills, 277 unfilled loaded pages; class counts 139/68/115/15/6/2/2. **Confirmed saved counts.** The split is URL-list membership, not proof each URL really presented its described flow. Bot-blocking explanation is **unverifiable belief**.
- Missing compressed/encrypted/custom-hash/worker traffic, limited card coverage, no deliberate submit/consent, one run/vantage and crude domain test. **Confirmed limits** of code and data. “leak rate is a lower bound” is **overstated** without accounting for false positives, selection and ownership errors.
- Lightpanda sink defaults and conceptual relation to dynstate. **Unverifiable external/prior claims**; these scripts do not reuse either.
- “Next steps [BELIEF]”. **Recommendations**, not measured claims.

## Additional regex-report claims

- “About 1 in 7 unique regexes in real code is super-linear”; “false for 14% ... checkable for the rest”. **Wrong/overstated.** These mix static-vulnerable counts (14.0% npm, 12.9% web) with dynamic heuristic counts (13.3%, 12.2%). Recheck has 241/129 unknowns; the remainder is not all established linear. Selected corpora do not support prevalence across real code generally.
- npm/web occurrence, unique and valid totals; recheck safe/vulnerable/unknown; polynomial/exponential counts; V8 counts and union counts. **Confirmed exactly** in regex/recount.json.
- Web “2,782 files, 278 MB”; “357 files failed full parse”. **Confirmed sizes/failure count, wrong parsing description.** Extractor metadata gives 278,353,971 characters, not a separately measured encoded byte count; failures are 231 npm + 126 web tokenizer failures. Acorn tokenizer is not a full parser.
- Literal and string-constructor extraction, concatenation skip, selected dependent-count corpus. **Confirmed implementation, limited completeness.** npm skips JS entries >=3 MB. Constructor detection also accepts a leading string without proving the remaining expression/flags are static or that RegExp names the builtin. No call-site reachability/use is retained.
- “V8 ... new RegExp(src, flags+'l')”. **Wrong exact method.** analyze.js removes g, y and l before adding l. Dynamic default-engine tests remove g and y too. Removing sticky y can enable search across input positions and alter performance. This needs explicit disclosure before attributing timings to the original regex usage.
- recheck version 4.6, bounded doubling, timeout/cap and confirmation definition. **Confirmed saved code/installation method, with qualification:** the actual slope filter uses points above 5 ms; a timeout or any caught exception is marked to=true. Timing is one observation per size, with no repeated-trial uncertainty.
- “none exceeded 500 ms” for l-compatible confirmed cases; medians 13/11 ms. **Confirmed saved values**, maxima 269.94/305.63 ms. Those are one attack input per case, not a general speed bound.
- “So l fixes ~70-72% of true positives.” **Wrong for web** (65.3%) and **overstated “true positives”**; static labels and heuristic observations do not establish every case. l engine compatibility also concerns changed flags.
- Unsupported backreferences/lookarounds. **Confirmed rejection categories in saved results**; “etc.” should not imply the list is exhaustive.
- Exponential examples and 79/48 labels. **Confirmed saved classifications.** Dynamic timeouts alone do not distinguish exponential from polynomial.
- “These are quadratic cases (^\\s+|\\s+$, \\/+$, #.*$)”. **Confirmed as recheck labels**, with two local samples reproducing approximately quadratic scaling. Exact complexity for every occurrence/use is unverified.
- “^\\s+|\\s+$ (111 packages, 43 sites; quadratic: 32 kB of spaces then a non-space took ~2 s)”. **Wrong attack description.** Saved attack is "'\\x00' + '\\t'.repeat(54773) + '\\t\\x00'": a leading nonspace is essential to avoid immediate success of the first branch. A local test of 32,768 spaces followed by x took 0.16 ms. Counts 111/43 refer specifically to the g-flag entry, not an occurrence-independent union across flags.
- The widely-seen lodash examples and package frequencies. **Confirmed saved extraction metadata only**; whether each copy executes on attacker input is unverified.
- “Safe ... is not a proof”; unknowns excluded; occurrence-weighted rates uncomputed; reachability untested; most hits on internal strings; unconfirmed candidates “likely false positives or too slow”. **First four confirmed limitations; last two unverifiable beliefs.** A particular timing threshold failure alone does not establish a false positive.
- Fetch/extraction runtimes and “5 min on 128 cores”. **Unverifiable historical timing**, not rerun.
- Rerun command “python3 -I agg.py from data/”. **Wrong path in stated recipe.** agg.py is in work/, not data/. Invoke python3 -I ../work/agg.py from data/. It also writes confirmed JSON files, so run a copied version in a private directory when reviewing.
