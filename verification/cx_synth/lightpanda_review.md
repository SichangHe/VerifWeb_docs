## Findings

1. **Wrong counts.** SUMMARY says “8 DOM/JS-state match; 6 differ”; REPORT says “DOM/JS state identical on 8 pages”. Original `js/diff_output.txt` ends with **“7/14 pages differ”**. Its seven differences include four network-only differences; only three pages differ on the checked state fields. Thus 7 pass the combined comparator, and 11 pass its state checks: 10 actually compared state samples match, one timer page skips state comparison, and three differ. Neither supports 8/6. Correct the counts and distinguish state from network comparison.

2. **Overstated termination.** “all 14 pages terminated in both engines” means navigation and one probe returned. `js/run.mjs` does `await p; await new Promise(r=>setTimeout(r,400));` before setting `res.terminated=true`; `js/server.mjs` explicitly includes `setInterval(function(){document.title=Date.now()},5)`. The script does not terminate. Rename this result “navigation/probe completed within the harness deadline”; do not treat it as termination verification. The comparator skips all state fields for this timer page and normalizes whitespace in other pages' strings, so “identical” also overstates exact state equality.

3. **Confirmed filter bypass, narrow scope.** Independent `lightpanda_copy/enforce_rerun.log` reproduces the saved results: without flags, six attack pages reach B; with `--block-urls '*127.0.0.1:18802*'`, output is `B-hits 1 beacon_ws:1`, with `GET /ws`. This establishes an HTTP request to the forbidden host from WebSocket initiation, not a successful WebSocket session. Server returns ordinary HTTP 200, not 101. Source `src/browser/webapi/net/WebSocket.zig:235` opens the connection directly, checks blocked ports, and contains no URL-blocklist call in `connect`. Keep the report's one-build/pattern qualification. Redirect to B was blocked in this test; a redirect-chain bypass is not established.

4. **Overstated isolated verification targets.** REPORT labels `URL.zig`, `Regex.zig`, `Arena*.zig`, etc. “small, pure, good first targets”. URL resolution delegates to `U.url_resolve_with_encoding` / `U.url_resolve_without_encoding` (`src/browser/URL.zig:40`), implemented through Rust's `url::Url`; Regex wraps PCRE2; arena modules manage mutable allocations. Verifying only those Zig wrappers would leave important semantics trusted. Identify particular pure functions and their dependencies before recommending a proof boundary. “not tractable” for Frame/V8/HttpClient is an unsubstantiated feasibility judgment, not a demonstrated limit.

5. **Unverified same-cause assertion.** A table width mismatch under `display:contents` does not establish the “same family” as descendants losing boxes in `WEB_FAILURE_TARGETS` #1. The original test does not compare a control without `display:contents` or inspect lost descendants. An independent paired control (`lightpanda_copy/control.mjs`, output `control.log`) returns `<title>[5,5]</title>`: both the ordinary table and the table inside `display:contents` have width 5 in Lightpanda. Thus the observed width is not specific to `display:contents`; preserve the measured mismatch but withdraw the asserted connection unless further evidence establishes it. The source has substantial width/layout logic; “no real layout” is imprecise. Upstream's precise wording is “No graphical rendering engine”.
